# 06 测试与验收

> 目标：每个设计承诺都有可执行的验证；不靠"跑通一次 demo"当质量证据。测试分层与门禁沿用 btry 既有实践，并针对 LLM/计量计费补充专项。

## 1. 测试策略总览

```text
                 ┌──────────────────────────────┐
                 │ 压测 / 故障注入 / 对账演练     │  证据：bench 报告、故障矩阵结果
                 ├──────────────────────────────┤
                 │ 集成测试（MySQL/Redis/真实协议）│
                 ├──────────────────────────────┤
                 │ Provider 契约测试（SPI 测试套件）│
                 ├──────────────────────────────┤
                 │ 单元测试（领域/策略/状态机/金额） │
                 └──────────────────────────────┘
架构门禁：ArchUnit + Spring Modulith + 数据边界 + KernelPurity + 表清单基线
```

原则：

- 模块测试不依赖真实 provider；provider 用可控 mock/simulator。
- 涉及金额/额度/状态机的逻辑必须有**不变量测试**与并发测试。
- 每个故障场景既测"行为"，也测"日志/指标/计费口径"。
- 所有性能结论必须来源可复现脚本 + 环境记录（与 btry/blrs 的基线方法一致）。

## 2. 单元测试

| 对象 | 用例 |
|---|---|
| Money/计价 | 舍入（向上/银行家）、币种/精度、阶梯价、免费额度、0 用量、极大 token 溢出边界、Decimal 不可变 |
| 计量聚合 | sum/count/unique/latest/max、窗口边界、乱序事件、重复 eventId、维度过滤 |
| 预扣/结算状态机 | PENDING→SETTLED/RELEASED/EXPIRED；settle+release=reserved；并发 expire/settle 只成功一次；部分结算 |
| 账本 | 借贷方向、余额推导、bizNo 唯一、负余额策略、拒绝直接改余额 |
| 账单 | 账期边界、调整单、finalize 后不可改、credit note |
| 策略解析 | 全局/租户/provider/model 覆盖顺序、默认值、非法配置快速失败 |
| 错误分类 | 每个 provider 错误码 → 内部 error_type/retryable/billable；未知码兜底 |
| 超时/重试 | 退避公式、jitter 范围、deadline 消耗、committed 后不重试、retry budget 耗尽 |
| 限流 | 令牌桶并发正确性（多线程）、窗口边界、Redis/本地兜底切换 |
| 熔断 | 状态迁移、最小样本、4xx 不计入、half-open 探测、CallNotPermitted |
| 路由 | 候选过滤/权重/fallback 深度/冷却跳过/无候选快速失败 |
| 流式 | 首 token 前/后失败语义、取消、部分用量估算、chunk 空闲超时 |
| 注解/AOP | 顺序、异常透传、自调用失效、Spring 代理边界 |
| 日志/脱敏 | JSON Schema 校验、敏感字段（密钥/PII/prompt）绝不出现、采样标记 |

工具：JUnit 5、AssertJ、Mockito、jqwik（property-based，金额/状态机可选引入）、ArchUnit、Spring Modulith。

## 3. Provider 契约测试（SPI Test Kit）

为 `ProviderAdapter` 提供一套可复用的**契约测试套件**，任何新 provider 实现必须通过：

- 正常请求 → 统一响应字段/usage 解析；
- 流式：正常 chunk、空 chunk、finish、usage 末尾、内容为空；
- 错误映射：400/401/403/404/429/500/502/503/529/超时/连接重置/内容过滤/上下文超长；
- 取消：中断/客户端断开时上游连接被关闭；
- 缺失 usage：返回 `source=ESTIMATED`；
- 幂等：同一 requestId 重试不产生重复副作用（若 provider 支持幂等键）。

实现方式：

- Mock provider：完全可控（延迟、错误、token 数、流中断、usage 缺失）。
- SSE/HTTP fixtures：录制真实响应（脱敏）作为回归样本，不依赖外网。
- 真实 provider（DeepSeek）：标记 `@Tag("real-provider")`，默认不在 CI 跑；手动执行并记录版本/日期。

## 4. 集成测试

| 场景 | 断言 |
|---|---|
| llm 调用 → outbox → metering 事件 | 事件落库、幂等重放不重复、metering 可见 |
| 预扣 → 结算 | 余额/账本/预扣状态一致；settle+release=reserved |
| 结算 worker 批量 | 批量事务原子性；崩溃后重启不丢/不重 |
| 出账/对账 | 账单金额=Σ计价；构造差异全部检出；不改历史 |
| 身份/API Key | 只存哈希、吊销生效、权限边界 |
| 模块边界 | ArchUnit/Modulith/数据边界/KernelPurity 全绿 |
| 日志/trace | 一次调用端到端断言 request_id/trace_id/字段完整性（可检索） |
| 配置 | 策略覆盖、密钥引用解析失败快速启动失败（不裸奔） |

环境：MySQL 8 + Redis（复用 btry 集成测试方式：`IT_DB_URL`/`IT_REDIS_*` 环境变量），单库 `atry_it`；Flyway 真实迁移；每个用例清理数据。

## 5. 故障注入矩阵（必须有结果记录）

| 故障 | 注入方式 | 期望行为 | 验证 |
|---|---|---|---|
| 上游 429（带/不带 Retry-After） | mock provider 配置 | 按指示/退避；不放大；日志 error_type=rate_limited | 重试次数、429 比例、计费=0 |
| 建连超时 / 首 token 超时 | mock 延迟/不可达 | 重试/fallback；committed 前不计费 | 超时分类、attempt 记录 |
| chunk 空闲超时 | mock 流暂停 | 中断、部分用量结算 | stream_interrupted 日志、金额 |
| 上游 5xx/529 | mock | 退避/fallback；熔断计数 | error 分布、熔断状态 |
| 流已输出后中断 | mock | 不重试、不续写；部分结算 | 无重复文本、金额正确 |
| 客户端断开 | 压测工具取消连接 | 取消上游（连接关闭）、部分结算 | 上游连接指标、金额 |
| 结算 worker 崩溃 | kill -9 | 重启后继续；不丢/不重 | 预扣终态、账本/事件一致 |
| DB 短暂不可用 | 断连接/停 MySQL（测试环境） | 调用侧快速失败；outbox 堆积告警；恢复后追上 | 错误码、指标、对账 |
| Redis 故障 | 停 Redis | 限流本地兜底；幂等本地兜底；不全局 429 | fallback 指标、成功率 |
| 重复投递/重复回调 | 同一事件投递 N 次 | 只入账一次 | 唯一键、金额 |
| 时钟偏移/乱序 | 构造 occurred_at 乱序 | 按规则入账/进人工，不产生负余额 | 对账、告警 |
| 价格版本切换 | 事件跨 effective 边界 | 各自价格版本、历史不变 | 账单/快照断言 |

每个场景输出：请求结果、错误分类、重试次数、计费金额、日志字段、指标变化、对账结果，沉淀到 `docs/bench/` 或 `docs/evidence/`。

## 6. 并发与性能测试

### 6.1 并发专项

- 多虚拟线程并发调用：验证 bulkhead/信号量上限、无泄漏、取消传播。
- 限流器并发正确性：N 线程同时打，允许数 = 配置值（误差 0）。
- 结算并发：同一账户/同一 reservation 并发 settle/expire；账户余额不为负、账本平衡。
- 队列背压：生产 > 消费时队列有界、拒绝策略触发、告警。
- 长连接：SSE 并发连接上限、断连清理、内存/线程稳定（跑 10min 观察）。

### 6.2 压测场景（mock provider）

| 场景 | 变量 | 指标 |
|---|---|---|
| 网关基线 | 并发 4/8/16/32，非流式 | QPS、p50/p95/p99、错误率、自身开销 |
| 流式 | 并发 8/16，mock 固定 chunk 延迟 | 并发流数、TTFT、chunk 间隔、断连率、内存 |
| 慢 provider 隔离 | 一个 provider 延迟 ×10 | 其他 provider 的 p99 是否受影响 |
| 过载 | 超过 maxInFlight 2–5 倍 | 拒绝率、排队时间、Retry-After、稳定性 |
| 结算 | 高频事件（10k/s 注入） | 队列深度、结算延迟 p99、DB 写入、对账 |
| 故障恢复 | 压测中停 Redis/DB/worker | 恢复时间、错误率、数据一致性 |

### 6.3 性能验收（首期目标，压测后校准）

- 网关自身开销（不含上游）：p99 < 15ms（4C8G，mock provider 0 延迟）。
- mock provider 非流式：≥ 1,000 req/s，p99 ≤ 200ms（含 mock 上游 IO）。
- 流式：≥ 500 并发流稳定 10min，无 FD/内存泄漏；TTFT p95 与 mock 配置偏差 ≤ 10ms。
- 结算：注入 5k events/s，结算延迟 p99 < 2s，队列不无界增长。
- 全链路对账：跑 10 万事件后差异 = 0。

压测脚本/报告放 `docs/bench/`，每次结论必须包含：环境（CPU/内存/MySQL 配置/连接池）、脚本 commit、原始输出、对照说明。

## 7. 架构与质量门禁

| 门禁 | 工具/位置 | 失败即红 |
|---|---|---|
| 模块依赖/循环 | Spring Modulith `modules.verify()` | 未声明依赖/循环 |
| 包级方向 | ArchUnit（扩展 `ModuleBoundaryTest`） | 反向依赖/直连实现 |
| 内核无业务词 | `KernelPurityTest`（扫描新模块） | 出现垂直词汇 |
| 数据边界 | 表访问清单基线 | 新增未登记表/跨模块访问 |
| 表命名 | 迁移扫描 | 非 `t_` 前缀/禁用词 |
| 日志 schema | JSON Schema 测试 | 字段缺失/类型错 |
| 敏感信息 | 日志扫描用例 | 密钥/prompt 明文 |
| 测试覆盖率（关键域） | JaCoCo（可选阈值） | metering/llm 核心包低于阈值 |

## 9. CI 与本地执行

```bash
# 单元 + 架构门禁（不依赖外部服务）
cd server && mvn -B test

# 集成（MySQL/Redis）
IT_DB_URL=... IT_DB_USER=... IT_DB_PASSWORD=... \
IT_REDIS_HOST=127.0.0.1 IT_REDIS_PORT=6379 IT_REDIS_DATABASE=15 \
mvn -B -Pintegration test

# 契约测试（mock provider）
mvn -B -Dtest='*ProviderContractTest' test

# 真实 provider（手动，需 key，不在 CI）
DEEPSEEK_API_KEY=... mvn -B -Dtest='*DeepseekContractTest' -Dgroups=real-provider test

# 压测（应用已启动）
./bench/run.sh <scenario> <concurrency> <duration>
```
