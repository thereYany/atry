# 05 通用计量计费设计

> 定位：metering 是 atry 的通用能力，和 identity/payment 同级。它不认识 LLM、不认识网课、不认识任何业务；只认 **metric（度量）、quantity（数量）、unit（单位）、price（价格）**。LLM token 只是第一个计费维度。
> 参考模型：Stripe Billing Meters、Metronome、Lago、OpenMeter 的共性抽象（见 07 调研），并按"预付费 + 高频事件 + 强一致账务"取舍。

## 1. 原则

1. **五层分离**：原始事件（不可变、可重放）→ 计量规则（可演进、不回填历史）→ 价格（版本化快照）→ 账单（商业凭证）→ 账本/收款（事实）。
2. **准入与账务分离**：实时准入用预扣/额度（低延迟、允许最终一致）；账务用不可变账本 + 异步结算 + 对账兜底。
3. **事件即事实**：用量事件 append-only，先落库/落 outbox，再算钱；任何金额都能从"事件 + 价格快照"重算。
4. **金额用十进制**：内部用整数最小单位或 `DECIMAL(20,6)`，禁止 double；只在出账边界舍入一次。
5. **幂等优先**：事件 ID 由业务确定性生成；重复投递只入账一次；预扣只能结算一次。
6. **可审计**：价格版本、规则版本、调整单、对账差异全部留痕，历史账单不可改。

## 2. 五层链路

```text
① 用量事件 UsageEvent             （append-only，幂等键 event_id）
      │  按 meter 过滤/聚合（sum/count/unique/latest/max，按 dimensions 分组）
      ▼
② 计量数量 MeteredQuantity         （窗口：分钟/小时/日；可重算）
      │  取事件发生时刻生效的价格版本
      ▼
③ 计价 RatedCharge                （quantity × unit_price，阶梯/套餐/折扣）
      │  汇总到账期
      ▼
④ 账单 Invoice                    （明细、合计、状态机；finalize 后不可改）
      │  收款/充值/信用
      ▼
⑤ 账本 Ledger + 余额/收款对账       （不可变流水，余额物化，五层一致性校验）
```

## 3. 计量模型

### 3.1 MeterDefinition

| 字段 | 说明 |
|---|---|
| meterKey | 稳定标识，如 `llm.tokens`、`api.requests`、`gpu.seconds` |
| eventName | 对应事件名，如 `llm.call.finished` |
| aggregation | sum / count / unique / latest / max（默认 sum） |
| unit | token / request / second / byte / call |
| dimensions | 可分组维度白名单（如 provider、model、token_type）；用于计价与报表 |
| filter | 事件过滤条件（如仅 status=ok、仅 billable=true） |
| window | 聚合窗口（minute/hour/day）；影响实时余额与报表 |
| version/status | 规则版本；变更只影响新事件，不回填历史 |

### 3.2 UsageEvent（不可变事实）

| 字段 | 说明 |
|---|---|
| eventId | 幂等键，业务确定性生成（如 `req_xxx:attempt:usage`） |
| meterKey | 归属计量 |
| subject | tenantId/appId/userId（归属主体，只存 ID） |
| quantity | Decimal 或整数 + unit（由 meter 定义单位） |
| dimensions | Map<String,String>，白名单维度，低基数 |
| occurredAt | 事件发生时间（决定账期与价格版本） |
| sourceRef | 来源引用（llm call record id / 外部系统单号） |
| status | RECEIVED / RATED / INVOICED / IGNORED（不对金额做原地修改） |
| ratingRef | 可选：关联计价结果；价格不在事件上固化，计价时按 occurredAt 取生效版本并写入 Charge |

不变量：同一 eventId 只入账一次；事件可重复投递但不能被修改；事件时间不可晚于接收时间过多（防乱序，超出窗口进人工/延迟队列）。

### 3.3 LLM 用量映射

| LLM 字段 | 映射 |
|---|---|
| usage.input_tokens | meter=`llm.tokens`, dimensions.token_type=`input` |
| usage.output_tokens | token_type=`output` |
| cached_read/cached_write/reasoning tokens | 各自 token_type（价格书可配不同单价） |
| usage.source | `PROVIDER` / `ESTIMATED`（估算进入 dimensions，便于对账筛选） |
| requestId/attempt | eventId = `requestId:attempt`（重试不发生重复计费） |
| provider/model | dimensions（低基数，用模型别名枚举） |

## 4. 计价（Rating）

### 4.1 PriceBook / RateCard

| 对象 | 字段 |
|---|---|
| PriceBook | bookKey、currency、version、effectiveFrom/To、status |
| RateCard | meterKey、subjectSelector（可选：租户/套餐）、unitPrice（Decimal）、tiers[]、rounding、createdAt |
| Tier | upTo（数量上限）、unitPrice、可选固定费 |

规则：

- 事件按 `occurredAt` 落在哪个 `effectiveFrom/To` 区间，取对应版本；**价格快照写入计价结果**，历史账单不受后续调价影响。
- 支持阶梯（前 N 免费/不同价）、套餐（月固定 + 超出单价）、按模型差价；先实现前两者与按维度定价，促销/优惠券后置。
- 舍入：按最小货币单位向上/银行家舍入二选一，全链路统一并在价格书声明；只在 rating 边界做一次。
- LLM 示例：`llm.tokens{token_type=input}` 单价 1 元/百万 token → `unitPrice=0.000001`（CNY/token，Decimal 6 位）。

### 4.2 计价结果

`RatedCharge`：eventId/meterKey、quantity、priceSnapshot（priceVersion、rateCardId、unitPrice、currency）、amount、ratedAt、ruleVersion。可重算、可审计、不可改。

## 5. 额度、账户与预扣

### 5.1 BillingAccount

| 字段 | 说明 |
|---|---|
| accountId | 账户 |
| subject | tenant/app/user（一个主体可有多币种账户，首期单币种） |
| balance | 可用余额（物化，来自账本） |
| creditLimit | 信用额度/透支上限（默认 0） |
| status | ACTIVE/FROZEN/CLOSED |

### 5.2 Entitlement / Grant（额度与赠送，与余额分离）

- Entitlement：套餐/功能额度（如每月 100 万 token），有 period/reset/overage 策略。
- Grant：一次性/周期性发放的额度（试用、补偿），有优先级、生效/过期时间、burn-down 记录。
- 扣减顺序：Grant（按优先级/最早过期）→ 余额 → overage（若允许）。
- 额度查询与账单解耦：Entitlement 是"实时控制面"，Invoice 是"账务面"。

### 5.3 Reservation（预扣）状态机

```text
PENDING ──settle(actual)──► SETTLED（部分结算：settle + release = reserved）
   │
   ├──release──► RELEASED（未产生用量/失败）
   └──expire───► EXPIRED（超时未结算，由 ReservationExpiryJob 回收）
```

- reserve 依据：LLM 按 `max_tokens × 单价上限` 估算；非 LLM 按调用方声明上限。
- 并发控制：同一 reservation 的状态 CAS；expire 与 settle 竞争只能成功一方（DB 条件更新/唯一约束）。
- 预扣记录持久化（短 TTL）；内存预扣仅作为准入加速，崩溃后以 DB reservation 为准重建。
- 预扣时同步增加 `account.frozen`（与 reservation 同事务）；settle 时 `frozen -= reserved` 并扣 `balance`；release/expire 时只回减 `frozen`。可用额校验基于 `balance − frozen`，防止并发预扣超卖。

## 6. 账本与账单

### 6.1 Ledger

| 字段 | 说明 |
|---|---|
| entryId | 唯一 |
| accountId | 账户 |
| direction | DEBIT/CREDIT（或带正负号的 amount） |
| amount + currency | Decimal + 币种 |
| bizType | RECHARGE / SETTLE / REFUND / ADJUST / GRANT_EXPIRE |
| bizNo | 业务单号（唯一约束，幂等） |
| balanceAfter | 物化余额（可选，必须可由流水重算校验） |
| createdAt | 不可变 |

- 余额 = 初始 + ΣCREDIT − ΣDEBIT；**可用额 = balance − frozen**（frozen 为未结算预扣之和）；定期用流水重算与物化余额比对（不一致告警）。
- 充值：`payment.PaymentSettledEvent` → 幂等入账（bizNo=paymentNo）；退款/拒付同理。

### 6.2 Invoice

- 生命周期：DRAFT → FINALIZED → (VOID / CREDIT_NOTE)；FINALIZED 后不可修改，只能冲正。
- 明细：meter、quantity、unitPrice、amount、dimensions；合计 = Σ明细 − credit − adjustment。
- 账期：自然月/自定义；预付费用户仍出"用量账单"（展示消耗，不重复收款）。
- 调整：补录/优惠/差错通过 adjustment/credit note，不改历史行。

## 7. 对账（Reconciliation）

五层一致性校验（按日/按账期）：

| 层 | 校验 |
|---|---|
| L1 事件 | 调用记录数/usage 事件数；重复/丢失（按 requestId） |
| L2 计量 | 事件聚合数量 = 计量数量（按 meter/dimensions/window） |
| L3 计价 | 计价金额 = quantity × priceSnapshot；价格版本正确 |
| L4 账单 | 账单金额 = Σ计价 − credit − adjustment |
| L5 收款 | 收款/充值 = 账单/账本对应流水；预扣全部终态（无悬挂 PENDING 超期） |

差异类型：`MISSING_EVENT`、`DUPLICATE_EVENT`、`AMOUNT_MISMATCH`、`PRICE_VERSION_MISMATCH`、`UNSETTLED_RESERVATION`、`LEDGER_INCONSISTENT`。差异进 `ReconDiff`，人工/自动调整，**不改历史事实**。LLM 场景额外与 provider 用量账单对账（如果 provider 提供）。

## 8. 一致性与并发（取舍）

### 8.1 热点账户方案对比

| 方案 | 优点 | 代价 | 采用 |
|---|---|---|---|
| A. 纯事件追加 + 异步聚合 | 无热点、可重放 | 余额最终一致，无法实时拦截 | 作为事实层基础 |
| B. 单账户行锁强扣 | 强一致、简单 | 千级 QPS 行锁冲突 | 仅作为结算/对账兜底 |
| C. 分桶/子账户 | 写扩展好 | 读放大、调账复杂 | 第二阶段（多实例） |
| D. Redis/内存预扣 + 异步落账 | 低延迟 | 宕机丢预扣、需对账回补 | **首期**（准入）+ DB reservation 持久化 |
| E. 窗口批量结算 | 大幅降事件量 | 延迟/超卖窗口 | 作为优化项（按 meter 配置） |

**首期决策**：D + A/B 组合——准入内存预扣 + 持久化 reservation；调用结束写 outbox；结算 worker 批量落账本/更新余额/写聚合；对账兜底。多实例时把预扣迁到 Redis（Lua，tenant 分桶），账务仍落 DB。

### 8.2 幂等与至少一次

- 事件：`eventId` 唯一键；outbox 至少一次投递；消费端幂等。
- 结算：reservation 状态 CAS + ledger `bizNo` 唯一。
- 出账：账期唯一约束；重复出账幂等返回。
- 外部对账：以 provider 账单/收款流水为准，差异走调整。

### 8.3 事务边界

| 操作 | 事务 |
|---|---|
| 记录事件 | 单表 insert（唯一键）+ 可选 outbox |
| 预扣 | 单行 insert/update（条件） |
| 结算批量 | 一个事务：ledger 批量 insert + account update + reservation update + 聚合 upsert |
| 出账 | 批量事务，账单+明细一起 |
| 对账 | 只读扫描 + 差异写入独立事务 |

## 9. 数据模型（首期）

```sql
-- 计量定义
t_metering_meter(id, meter_key, event_name, aggregation, unit, dimensions_json,
                 version, status, created_at, UNIQUE(meter_key, version));

-- 用量事件（append-only）
t_metering_usage_event(id, event_id CHAR(64) UNIQUE, meter_key, tenant_id, app_id, user_id,
                       quantity DECIMAL(20,6), unit, dimensions_json, occurred_at DATETIME(3),
                       received_at DATETIME(3), source_ref, status, charge_id NULL,
                       KEY idx_usage_meter_time(meter_key, occurred_at),
                       KEY idx_usage_tenant_time(tenant_id, occurred_at));

-- 价格书/费率
t_metering_price_book(id, book_key, currency, version, effective_from, effective_to, status,
                      UNIQUE(book_key, version));
t_metering_rate_card(id, book_id, meter_key, subject_selector, unit_price DECIMAL(24,12),
                     currency, tiers_json, rounding, created_at);

-- 账户/额度
t_metering_account(id, tenant_id, app_id, user_id, currency, balance DECIMAL(20,6),
                   frozen DECIMAL(20,6) NOT NULL DEFAULT 0,
                   credit_limit DECIMAL(20,6), status, version,
                   UNIQUE(tenant_id, app_id, user_id, currency),
                   CHECK (balance >= 0 AND frozen >= 0));
t_metering_entitlement(id, subject..., meter_key, quota DECIMAL(20,6), period, reset_policy,
                       priority, effective_from, effective_to, status);
t_metering_grant(id, entitlement_id, amount, remaining, priority, effective_from, effective_to, status);

-- 预扣
t_metering_reservation(id, reservation_id CHAR(32) UNIQUE, account_id, amount DECIMAL(20,6),
                       currency, status, biz_ref, expires_at, settled_at, created_at,
                       KEY idx_reservation_status_expire(status, expires_at));

-- 账本
t_metering_ledger(id, account_id, direction, amount DECIMAL(20,6), currency, biz_type, biz_no,
                  balance_after DECIMAL(20,6), created_at,
                  UNIQUE(biz_no), KEY idx_ledger_account_time(account_id, created_at));

-- 计价结果
t_metering_charge(id, event_id, meter_key, quantity, amount DECIMAL(20,6), currency,
                  price_version, rate_card_id, price_snapshot_json, rule_version, rated_at,
                  UNIQUE(event_id));

-- 账单
t_metering_invoice(id, invoice_no, tenant_id, app_id, period CHAR(7), currency,
                   subtotal, credit_total, adjustment_total, total, status,
                   finalized_at, created_at, UNIQUE(tenant_id, app_id, period, currency));
t_metering_invoice_line(id, invoice_id, meter_key, dimensions_json, quantity, unit_price, amount);

-- 对账
t_metering_recon_run(id, run_no, period, layer, status, checked_count, diff_count, started_at, finished_at);
t_metering_recon_diff(id, run_id, layer, diff_type, biz_ref, expected, actual, detail, status,
                      handled_by, handled_at);
```

- 所有表带 `tenant_id`（账户/账单/事件）；dimensions 用 JSON 但只允许白名单键，避免高基数。
- 保留：事件按账期归档（分期表/分区），账本与账单永久（或按合规）；对账差异长期保留。
- 迁移：Flyway，前缀 `V2xx__metering_*.sql`；新增表必须写入数据边界 baseline。

## 10. 多租户与公平性

- subject 三层：tenant → app → user；配额/余额可按 tenant 或 app 维度配置（首期 tenant）。
- 每租户配额独立，全局配额兜底；加权队列防大租户挤占；成本看板按租户/模型归因。
- 数据隔离：查询强制 tenant 条件（复用 btry 租户规范）；跨租户管理接口仅运营端。

## 11. 与 payment 的集成（后续迭代）

```text
payment 支付成功（PaymentSettledEvent，bizType=RECHARGE）
  → metering 消费（幂等，bizNo=paymentNo）
  → ledger CREDIT（RECHARGE）
  → balance 更新
```

- 充值单与账户绑定关系由业务侧（或充值模块）提供；metering 只认"收款事实"。
- 退款/拒付：反向 ledger 分录，不删历史。

## 12. 验收（详见 06）

- 不变量测试（同一事件重复投递、并发 settle/expire、负数、舍入、价格版本）。
- 对账：构造 L1–L5 差异，验证全部可检出且不改历史。
- 压测：事件写入 QPS、结算吞吐、账户热点、对账耗时；与基线对照。
- 故障：结算 worker 崩溃、DB 隔离、Redis 故障、outbox 堆积后的恢复。
