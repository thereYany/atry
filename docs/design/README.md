## 设计要点（TL;DR）

- **两个新模块**：`llm`（调用治理）+ `metering`（通用计量计费）；只依赖 `platform` + `contracts`，业务无关（artifact 前缀待 D1 决定）。
- **LLM 调用**：provider SPI、路由/fallback、四层超时、单点重试、熔断、bulkhead、多维限流、SSE 流式；默认 MVC + 虚拟线程。
- **可观测**：所有调用产出 `llm.call.*` 结构化日志 + OTel span + 低基数指标；注解/AOP 提供声明式入口；内容默认不落日志。
- **计量计费**：五层链路（事件→计量→计价→账单→账本/对账）；预扣/结算分离；金额十进制、不可变账本、历史不可改。
- **验证**：架构门禁 + 契约测试 + 故障注入矩阵 + 压测基线；每阶段有 DoD。

## 评审 checklist

- [ ] atry 仓库形态（D1）与模块命名（D2）已由 owner 确认
- [ ] API Key 归属（D3）、首期真实 provider（D4）、线程模型（D5）确认
- [ ] 领域模型/不变量无遗漏；错误分类与计费口径一致
- [ ] 可靠性默认值有压测/线上校准计划
- [ ] 日志 schema 字段满足"agent 一条日志定位"目标
- [ ] 数据模型/索引/保留策略评审通过
- [ ] 测试矩阵覆盖主要故障与并发场景；CI 门禁可落地
- [ ] 迭代计划与验收标准明确，未擅自扩大范围
