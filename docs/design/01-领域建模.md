# 01 领域建模

> 本文只做建模：限界上下文、聚合、实体/值对象、领域事件、契约与不变量。实现细节（表结构/接口签名）在 02、05 中给出。

## 1. 限界上下文（Bounded Contexts）

| 上下文 | 职责 | 拥有的事实 | 不负责 |
|---|---|---|---|
| `identity`（已有） | 主体身份：租户、用户、角色权限、**API Key 凭证** | 账号、角色、密钥哈希/状态 | 调用计量、计费 |
| `llm`（新增） | LLM 调用的**治理层**：provider 抽象、路由、调用执行、流式、容错、回退 | provider 配置、路由策略、调用尝试/结果（调用记录） | 计费口径、价格、余额 |
| `metering`（新增） | **通用计量计费**：用量事件、计量规则、价格/计价、额度/预扣、账本、账单、对账 | 用量事件、价格书、账户/流水、账单、对账 | 具体调用协议、provider 细节 |
| `platform`（已有） | 横切：租户、追踪、告警、审计、AOP、统一异常、缓存/限流基础设施 | trace/metric/audit/alert | 领域逻辑 |
| `payment`（已有） | 充值/收款（未来与 billing account 通过事件集成） | 支付单、退款、对账 | 用量与计价 |
| `contracts`（已有） | 跨模块稳定契约：接口、DTO、事件 | 无状态 | 任何实现 |

### 上下文映射

```text
             ┌──────────────┐        ┌─────────────────────────────┐
  调用方 ───►│  llm 上下文   │───────►│ metering 上下文（通用）       │
             │ 路由/调用/流式│ 契约   │ 用量→计量→计价→额度→账本/账单 │
             └──────┬───────┘        └──────────────┬──────────────┘
                    │ 事件 LlmCallCompleted/...      │ 事件 UsageRecorded/BalanceChanged/InvoiceIssued
                    ▼                                ▼
             ┌──────────────────────  contracts（接口 + DTO + 事件） ──────────────────────┐
             │  identity.ApiKeyOperations   metering.MeteringOperations   llm.LlmInvocationOperations │
             └──────────────────────────────────────────────────────────────────────────────────────┘
                    ▲                                                        ▲
                    │                                                        │
             ┌──────┴───────┐                                        ┌───────┴───────┐
             │  identity     │                                        │   payment     │
             │ 主体/API Key  │                                        │ 充值/收款事件  │
             └──────────────┘                                        └───────────────┘
```

依赖规则（与 btry 现状一致，新增模块沿用）：

- `llm`、`metering` 只能依赖 `platform` 与 `contracts`；禁止互相依赖实现，只能通过 `contracts` 或领域事件。
- `llm` 在调用前通过 `contracts.metering.MeteringOperations` 做额度预扣；调用结束后提交用量（或发事件，由 metering 消费）；是否同步/异步由配置决定（见 02 §5）。
- `metering` 不依赖 `llm`：LLM 的 usage 只是"一种 meter 的事件"，metering 看不到 provider/协议。
- `identity` 提供 `ApiKeyOperations`；`llm` 只拿 `SubjectRef`（tenant/app/user），不碰凭证表。
- `payment` 与 `metering` 通过 `PaymentSettledEvent` 集成：充值成功 → `metering` 入账（未来迭代，不在本期实现）。

## 2. llm 上下文模型

### 2.1 聚合与实体

| 对象 | 类型 | 关键属性 | 说明 |
|---|---|---|---|
| `ProviderDefinition` | 聚合根 | providerId, type, capabilities, status | provider 厂商/协议能力（不含具体接入） |
| `ProviderDeployment` | 聚合根 | deploymentId, providerId, endpoint, credentialRef, modelMapping, limits, healthRef | **一次具体接入**（同 provider 可多 deployment：区域/账号/配额不同）；凭证只存引用 |
| `ModelAlias` / `ModelGroup` | 聚合根 | alias, modelGroup, candidates[deployment], constraints | 客户端只认别名；同名模型跨 deployment 组成 group，支持同组重试/跨组 fallback |
| `ModelDefinition` | 实体 | providerId, modelName, contextWindow, supportsStream/tools, priceRef? | 模型元数据；价格不属于 llm（属于 metering 的价格书） |
| `RoutePolicy` | 聚合根 | taskType, alias, candidates[deployment/model/weight], fallbackChain, constraints | 路由策略：按任务/租户/成本/延迟选择候选链 |
| `CallExecution` | 聚合根（运行时） | requestId, subject, request, attempts[], state, timestamps | 一次逻辑调用，可含多次 attempt；持久化为调用记录用于排障/对账 |
| `Attempt` | 实体 | attemptNo, provider, model, startedAt, ttft, status, error, usage | 单次上游尝试；重试/切换 provider 产生新 attempt |
| `ProviderHealth` | 实体 | providerId, window, successRate, errorRate, p99Ttft, circuitState | 被动健康统计 + 熔断状态 |

### 2.2 值对象

| 值对象 | 字段 | 约束 |
|---|---|---|
| `LlmRequest` | operation(chat/embedding/…), modelHint, messagesRef, parameters, stream, requestId, tenantId/appId/userId, deadlineAt, budgetRef | 内容不落库；`messagesRef` 指向受控存储或直接内存传递 |
| `LlmResponse` | contentRef, finishReason, modelServed, providerRequestId, usage | 内容默认不持久化 |
| `Usage` | inputTokens, outputTokens, cachedReadTokens, cachedWriteTokens, reasoningTokens, source(PROVIDER/ESTIMATED) | 计量口径唯一来源；provider 未返回时估算并标记 |
| `LlmError` | category, providerCode, httpStatus, retryable, billable, message(脱敏) | 分类枚举见 03 §6 |
| `TimeoutPolicy` | connect, timeToFirstToken, chunkIdle, requestTotal | 四层拆分（见 04） |
| `RetryPolicy` | maxAttempts, initialBackoff, maxBackoff, multiplier, jitterRatio, retryBudget | 只对幂等调用/未提交响应生效 |
| `CircuitPolicy` | failureRateThreshold, slowCallRateThreshold, minCalls, openWait, halfOpenProbes | 粒度 provider × model |
| `RateLimitPolicy` | rpm, tpm, maxInFlight, dailyQuota, burst | 多维限流；租户级独立配额 |
| `RouteCandidate` | providerId, model, weight, maxCostPerCall, priority | 路由输入 |
| `SubjectRef` | tenantId, appId, userId | 全链路归属；只放 ID，不放明文密钥 |

### 2.3 关键状态机

```text
CallExecution:  CREATED ──reserve ok──► RESERVED ──upstream first byte──► STREAMING/WAITING
                   │                        │                                  │
                   │ reserve fail           │ upstream fail                    │ success/fail
                   ▼                        ▼                                  ▼
                REJECTED              FAILED(attempt++, may retry/fallback)   COMPLETED / FAILED / CANCELLED
```

- 收到**首个 token/响应头**后视为 committed：不再重试、不再 fallback（流式语义见 04 §8）。
- 每次 attempt 失败按错误分类决定：重试（同 provider）、fallback（换 provider/model）、终止。
- 调用结束必须产生 `LlmCallCompleted` 或 `LlmCallFailed`；预扣在两种情况下都要 settle/release，超时由 `ReservationExpiryJob` 回收。

### 2.4 领域事件（llm 发布）

| 事件 | 时机 | 关键载荷（脱敏） | 消费者 |
|---|---|---|---|
| `LlmCallStarted` | 进入执行 | requestId, subject, taskType, route | 观测/审计（可选） |
| `LlmCallCompleted` | 正常结束 | requestId, subject, provider, modelServed, usage, latency, attemptCount, priceVersionHint? | metering（记用量）、观测 |
| `LlmCallFailed` | 最终失败 | requestId, subject, errorCategory, retryable, attemptCount, partialUsage? | metering（失败是否计费按策略）、告警 |
| `LlmStreamInterrupted` | 流中断 | requestId, emittedTokens(估算), provider, reason | metering（按已产生 token 结算）、观测 |

## 3. metering 上下文模型

> 建模参考 Stripe Billing Meters / Metronome / Lago / OpenMeter 的共性抽象，并适配"预付费 + 高频事件 + 强一致账务"的诉求。详细五层链路见 05。

### 3.1 聚合与实体

| 对象 | 类型 | 关键属性 | 说明 |
|---|---|---|---|
| `MeterDefinition` | 聚合根 | meterKey, eventName, aggregation(sum/count/unique/latest/max), unit, dimensions, version, status | 计量规则；规则演进不回填历史 |
| `UsageEvent` | 聚合根（不可变） | eventId(idempotencyKey), meterKey, subject, quantity, dimensions, occurredAt, sourceRef, priceSnapshot? | 事实源；重复投递按 eventId 去重 |
| `PriceBook` / `PriceVersion` | 聚合根/实体 | bookKey, currency, version, effectiveFrom/To, rateCards | 价格版本化；事件发生时间取生效版本 |
| `RateCard` | 实体 | meterKey, subjectSelector, unitPrice(Decimal), tiers[], rounding | 计价规则；支持阶梯/套餐/按模型 |
| `BillingAccount` | 聚合根 | accountId, subject, currency, balance, frozen, creditLimit, status | 余额/冻结为物化视图；只能在账本/账户事务内变更；可用额 = balance − frozen − creditLimit 使用量 |
| `Entitlement` / `Grant` | 聚合根 | subject, feature/meter, quota, period, resetPolicy, grants[] | 额度/套餐（如免费额度、试用包） |
| `Reservation` | 聚合根 | reservationId, accountId, amount, status(PENDING/SETTLED/RELEASED/EXPIRED), expiresAt | 预扣；support 部分结算/超时回收 |
| `LedgerEntry` | 实体（不可变） | entryId, accountId, direction(DEBIT/CREDIT), amount, currency, bizType, bizNo, balanceAfter | 复式/单式均可，但必须可推导余额；不可修改 |
| `Invoice` | 聚合根 | invoiceNo, subject, period, lines[], status(DRAFT/FINALIZED/VOID), totals | 后付费账期凭证；finalize 后只能 credit note |
| `ReconciliationRun` / `Diff` | 聚合根/实体 | runId, period, sourceA/B, counts, amounts, diffs[] | 对账结果；差异进 adjustment，不改历史 |

### 3.2 值对象

`Money`（Decimal + currency + scale）、`Quantity`（value + unit）、`TokenUsage`（分项）、`MeterKey`、`PriceSnapshot`（priceVersion, unitPrice, currency, rateCardId）、`BillingPeriod`、`IdempotencyKey`、`SubjectFilter`、`Tier`、`Adjustment`、`ReservationRef`。

### 3.3 领域事件（metering 发布/消费）

| 事件 | 方向 | 用途 |
|---|---|---|
| `UsageSubmitted` / `UsageRecorded` / `UsageDuplicated` | 内部/发布 | 事件入库、去重、可观测 |
| `ReservationPlaced` / `ReservationSettled` / `ReservationExpired` | 发布 | 额度生命周期，供审计/告警 |
| `BalanceChanged` | 发布 | 流水的物化结果，供通知/看板 |
| `InvoiceDrafted` / `InvoiceFinalized` / `InvoiceVoided` | 发布 | 账单生命周期 |
| `ReconciliationMismatchDetected` | 发布 | 对账差异告警 |

### 3.4 关键不变量（硬约束）

1. 同一 `usage_event_id` 只能入账一次（唯一键 + 幂等处理）。
2. 账本流水不可变；账户余额 = Σ流水（或可被重放校验），禁止直接 UPDATE 余额绕过流水。
3. 预扣只能结算一次：`settle + release = reserved`；过期回收与结算并发时只能成功一方。
4. 账单金额 = Σ评级费用 − credit − adjustment；finalize 后不可改，只能 credit note/void。
5. 计费数量 = 去重后有效事件聚合；与对账快照在容差内一致，否则产生 diff。
6. 价格按 `occurredAt` 取生效版本；计价结果（Charge）保存价格快照，价格调整不影响历史。
7. 预付费余额不得为负；若允许 overage，必须有显式上限与告警。
8. 金额用十进制整数/Decimal（禁止 double），只在出账边界舍入一次；单位/币种全程一致。
9. LLM 调用失败时是否计费必须由策略决定，且与 `LlmError.billable` 一致；不允许同一失败在不同链路口径不同。

## 4. contracts 契约设计（只列语义，不含实现）

### 4.1 `contracts.identity`

| 契约 | 能力 |
|---|---|
| `ApiKeyOperations` | 创建/吊销 API Key（只返回一次明文）、按密钥认证返回 `SubjectRef` + scopes |
| （已有）`AccountDirectory` / `UserAccountOperations` 等 | 账号/角色查询 |

### 4.2 `contracts.llm`

| 契约 | 能力 | 备注 |
|---|---|---|
| `LlmInvocationOperations` | `invoke(LlmRequest)` / `stream(LlmRequest, StreamSink)` | 业务方唯一入口；内部负责路由/重试/降级/观测 |
| `LlmAdminOperations` | provider/route 配置管理（管理端） | 可选，首期只读配置 |
| `LlmCallRecordQuery` | 按 requestId 查询调用记录（脱敏） | 排障/客服使用 |

### 4.3 `contracts.metering`

| 契约 | 能力 |
|---|---|
| `MeteringOperations` | `recordUsage(UsageCommand)`、`reserve(ReserveCommand)`、`settle(SettleCommand)`、`release(ReleaseCommand)`、`queryBalance(subject)`、`queryUsage(query)` |
| `PriceAdminOperations` | 价格书/费率卡维护（管理端，可选） |
| `InvoiceOperations` | 账单查询/出账（管理端，后续迭代） |
| `EntitlementOperations` | 额度查询/发放（后续迭代） |

> 事件契约放在 `contracts.metering.events` / `contracts.llm.events`，使用不可变 record；跨模块消费必须幂等。

## 5. 模块依赖与命名

| 模块 | allowedDependencies | 包根 | 表前缀 |
|---|---|---|---|
| `platform` | — | `com.wherelee.base.modules.platform` | `t_*`（平台表） |
| `contracts` | platform | `...modules.contracts` | 无 |
| `identity` | platform, contracts | `...modules.identity` | `t_user*` 等 |
| `payment` | platform, contracts | `...modules.payment` | `t_payment_*` 等 |
| `llm` | platform, contracts | `...modules.llm` | `t_llm_*` |
| `metering` | platform, contracts | `...modules.metering` | `t_metering_*` |

新增 ArchUnit 规则（与现有 `ModuleBoundaryTest` 同风格）：

- `llm` / `metering` 不得依赖 `identity`、`payment`、`app`；
- `platform` / `contracts` 不得依赖 `llm` / `metering`；
- `contracts` 不得依赖 `llm` / `metering` 实现；
- `app` 只能通过 contracts 使用内核能力（示例宿主）。

## 6. 术语表

| 术语 | 含义 |
|---|---|
| Provider | LLM 服务提供方（OpenAI 兼容/DeepSeek/…） |
| Attempt | 一次上游尝试；一次逻辑调用可含多个 attempt |
| Usage | 实际消耗量（token 等），有 provider/估算两种来源 |
| Meter | 计量定义：对哪类事件、用什么聚合、什么单位 |
| Rating | 按价格书把用量换算成金额 |
| Entitlement/Grant | 额度/套餐/赠送额，与余额分离 |
| Reserve / Settle / Release | 预扣 / 按实际结算 / 释放预扣 |
| Ledger | 不可变资金流水 |
| Invoice | 账期账单 |
| Reconciliation | 对账：事件→计量→计价→账单→收款的一致性校验 |
